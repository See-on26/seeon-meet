# seeon 개발자 문서

[README](../README.md) 는 제품을 쓰는 사람 기준으로 적었어요. 이 문서는 앱을 직접 실행하고 고치는 사람을 위한
실행 방법·설정 값·세부 규칙을 모아 둔 곳이에요.

---

## 소스에서 실행하기

```bash
# 1) 의존성 설치
npm install

# 2) 환경 변수 준비 (실서버·Bedrock을 쓸 때만 값 채움)
cp .env.example .env

# 3) 앱 실행
npm start
```

서버 없이 화면만 둘러보고 싶다면, 터미널 한 곳에서 `npm run mock`, 다른 곳에서 `npm start` 를 실행해요.
목 서버가 화면 해설 서버를 흉내 내서 UI를 확인할 수 있어요.

---

## 화면 해설 AI 서버

앱은 `127.0.0.1` 의 아래 포트에 연결해요. 서버를 다른 컴퓨터에 띄웠다면 이 포트들로 이어 두면 돼요.

| 포트 | 하는 일 |
|---|---|
| 8801 | VLM — 화면을 읽어 해설을 만든다 |
| 8802 | ASR — 회의 소리와 음성 질문을 받아쓴다 |
| 8803 | TTS — 안내를 목소리로 바꾼다 |
| 8804 | 임베딩·OCR — 화면 전환 판정과 화면 글자 읽기 |
| 8805 | 판정 LLM — 발화가 정보 공백을 남겼는지 판단한다 |

연결 상태는 [개발자 모드](#개발자-모드)의 `GPU 서버` 줄에서 볼 수 있어요.

앱은 켜질 때 `.env` 의 서버 주소·계정·호스트 키 지문·키 경로로 GPU 서버에 SSH 터널을 직접 열어요([환경 변수](#환경-변수)).
넷 중 하나라도 없으면 터널을 열지 않고 `서버 설정 없음`(또는 `키 없음`)으로 알려요. 이미 다른 터널이 이 포트들을 쓰고 있으면 그 터널을 써요.
서버 주소·계정·포트·키는 저장소에 적지 않아요 — 실제 값은 `.env` 에만 넣어요.

## 환경 변수

`.env` 의 주요 값이에요.

| 변수 | 의미 | 기본값 |
|---|---|---|
| `SEEON_VLM_URL` | 화면을 읽는 서버 | `http://127.0.0.1:8801/...` |
| `SEEON_VLM_MODEL` | 화면을 읽는 서버에 요청할 모델 이름. 서버의 서빙 이름(`--served-model-name`)과 같아야 한다 | `gemma-4-26b-a4b-qat` |
| `SEEON_VLM_MAX_SOFT_TOKENS` | 화면을 읽는 서버가 그림 한 장을 나눌 이미지 토큰 수 상한(해상도)을 요청마다 넣는다. 서버를 `--trust-request-mm-kwargs` 로 띄웠을 때만 쓴다 — 그 옵션 없이 떠 있으면 요청별 값이 400 으로 거절돼 그림 요청이 모두 실패한다 | 꺼짐 (비우면 서버에 띄운 값) |
| `SEEON_ASR_URL` | 소리를 받아쓰는 서버 | `http://127.0.0.1:8802/asr` |
| `SEEON_TTS_URL` | 안내를 목소리로 바꾸는 서버 | `http://127.0.0.1:8803/tts` |
| `SEEON_JUDGE_BACKEND` | 탐지 단계 LLM 판정(통합 라우터·무발화·지시 판정)을 어디서 할지. `gpu` 는 GPU 서버 LLM 만 쓰고 실패해도 Bedrock 으로 넘기지 않는다(그 판정은 공백 아님으로 본다), `bedrock` 은 Bedrock 만 | `gpu` |
| `SEEON_JUDGE_GPU_MODEL` | 판정에 쓸 GPU LLM (주소는 `SEEON_JUDGE_GPU_URL`). VLM 과 같은 모델을 따로 띄운다 | `gemma-4-26b-a4b-qat` (`127.0.0.1:8805`) |
| `SEEON_GAP_SOURCE` | 교차 모드(품질·균형)에서 해설을 넣을 틈을 무엇으로 찾을지. `asr` 은 받아쓰기 조각 끝 시각, `audio` 는 앱이 잰 회의 소리의 무음 구간(넣기 직전에 조용한 자리로 다시 맞춘다) | `asr` |
| `SEEON_ROUTER_SCALE_ENABLED` | 추상적 척도 해설("꽤 넓죠"). `false` 면 끈다 | 켜짐 |
| `SEEON_FACT_COMPLETE_ENABLED` | 식별 사실 완결. 지시 해설(단순형)은 대상 뒤에 그 대상을 가르는 사실(개수·범위·조건·지명·비교 상대·시점) 칸을 잇고, 수치 해설은 값을 읽은 화면 줄을 근거 칸에 먼저 적게 하며, 잘린 지시·수치 칸의 범위 끝("…12월까지")을 떼지 않는다. 이은 지시 해설은 렌더러 단순형 최댓값(7어절) 안에서만 사실을 붙이고(caption 은 자르지 않고 끝의 자료 종류 낱말만 뗄 수 있다), seen 에 없는 숫자가 든 사실은 읽지 않고 기록(`droppedFact`)에 남긴다. `false` 면 예전 칸·자르기로 돌아간다 | 켜짐 |
| `SEEON_TIME_MARK_ENABLED` | 시점 표기 지키기. 수치 해설 예산을 맞출 때 대상 칸의 연도·분기·월·주를 꾸밈말보다 늦게 빼고, 근거 칸(지시 seen·수치 source)에 하나뿐인 시점이 해설에서 빠졌으면 대상 앞에 되살린다. 시점이 둘 이상·나열("2023, 2024년")·비교 기준·자료 속 항목 이름·시간 축 자료(근거 칸이나 해설에 월별·분기별 등)·문서 작성일/출처 연도면 되살리지 않고, 읽히는 낱말을 밀어내야 할 때도 붙이지 않는다. 되살린 시점은 기록(`restoredTimeMark`)과 흐름 창에 남는다. 수치 해설의 근거 칸(source)은 `SEEON_FACT_COMPLETE_ENABLED` 가 두는 칸이라, 그것을 끄면 지시 해설만 되살린다. `false` 면 끈다 | 켜짐 |
| `SEEON_SCREEN_VALUE_FIRST_ENABLED` | 발화 어림 되풀이 막기. 발표자가 어림해 말한 수("약 3천", "3천 명쯤")를 수치·척도 프롬프트에서 짚어, 화면에 글자로 적힌 값이 있으면 그 값을 쓰게 하고 그 값에 가까운 수가 든 OCR 줄을 먼저 넣는다. 라벨 없는 막대·선 높이를 읽는 일은 하지 않는다(`SEEON_CHART_ESTIMATE=on` 으로 「그래프 어림값」이 들어가면 적힌 값 다음으로 그 값을 쓰게 한다). 값→의미 해설의 값이 발화의 수(어림 값이면 ±15%)와 멀면 옆 대상의 값으로 보고 읽지 않는다(기록 `value-far-from-spoken`). `false` 면 끈다 | 켜짐 |
| `SEEON_SCALE_VALUE_FIRST_ENABLED` | 척도 해설을 적힌 값 먼저로. 대상 둘레에 글자로 적힌 값(통계 패널·툴팁·범례·데이터 라벨·눈금)을 근거 칸에 먼저 적고 그 값이나 화면 속 다른 대상과 견준 크기로 말한다. 대상이 보이면 거절하지 않고(대상이 없거나 값·견줄 것이 전혀 없을 때만 NONE), 자료 이름만 안내된 대상도 정도를 말한다. 통계 낱말이 든 OCR 줄을 먼저 넣는다. 척도 해설의 수(견준 배수·분수 제외)는 수치 해설처럼 화면 글자와 대조해, 없으면 읽지 않는다(기록 `value-absent`). `false` 면 예전 "비교 대상" 프롬프트 | 켜짐 |
| `SEEON_SPEECH_ROI` | 발화로 ROI 잡기(`on`·`off`). 발화 명사·숫자+단위·영문 약어를 화면 OCR 줄 위치와 맞춰 그 둘레를 확대하고, 지시·수치·척도 해설 요청 하나에 [화면 전체, 확대] 두 장을 넣는다. 끄면 요청이 지금과 같다. 세부: `SEEON_SPEECH_ROI_TYPES`(유형 쉼표 목록, 기본 `deixis,interpretation,visual_description`), `SEEON_SPEECH_ROI_FRAME_OCR`(지시 요청에도 같은 프레임 OCR, 기본 `off`), `SEEON_SPEECH_ROI_POINTING_PAIR`(가리킨 영역만 있는 지시 해설도 두 장, 기본 `on`) | `on` |
| `SEEON_CHART_ESTIMATE` | 수치 해설 때 화면의 세로 막대그래프(한 계열·값 라벨 없음) 막대 값을 세로축 눈금 OCR 줄과 화소로 어림할지. `off` 는 하지 않음, `log` 는 계산해 기록(해설 레코드 `screenText.chart`)과 `out/chart-frames/` 에만 남기고 프롬프트·값 검사는 그대로, `on` 은 「그래프 어림값」을 수치 에이전트에 넘기고 값 검사에서 어림값을 인정한다(늘 "약"을 붙여 읽음). 조금이라도 애매하면 건너뛴다. 화면 글자 근거(`SEEON_SCREEN_TEXT_GROUNDING`)가 꺼져 있으면 하지 않는다 | `off` |
| `SEEON_FACT_CARD` | 화면 사실 카드(`on`·`off`). 새 슬라이드가 확정될 때 화면을 읽는 서버에 한 번 물어 패널별 사실(라벨·값·단위·범례)을 카드로 만들어 두고, 해설 때 발화와 가까운 카드를 받는 에이전트의 프롬프트에 넣는다. 끄면 프롬프트가 지금과 같다. 세부: `SEEON_FACT_CARD_AGENTS`(받는 에이전트 쉼표 목록, 기본 `interpretation,scale`, `deixis` 도 고를 수 있음), `SEEON_FACT_CARD_JSON_MODE`(카드 JSON 을 받는 방법, `prompt` 만) | `on` |
| `SEEON_SCREEN_CHANGE` | 같은 슬라이드 안 화면 변화 해설. `off` 는 감지·기록을 하지 않음, `shadow` 는 감지·글자 차이·이미 말한 값 거르기까지 하고 기록만 남김(해설 없음), `same_slide` 는 새 글자·강조가 나타나면 변화 해설을 내고 근거가 늦게 뜬 해설을 다시 시도한다. `all` 은 아직 `same_slide` 로 돈다. 세부: `SEEON_SCREEN_CHANGE_KINDS`(사건 종류 쉼표 목록, 기본 `new_text,highlight`, 글자 없는 변화 `visual` 은 오탐이 많아 기본에서 뺌), `SEEON_SCREEN_CHANGE_MIN_INTERVAL_MS`(변화 해설끼리 간격, 기본 `20000`), `SEEON_SCREEN_CHANGE_PER_SLIDE_MAX`(슬라이드당 상한, 기본 `2`), `SEEON_SCREEN_CHANGE_IMAGE`(보내는 그림 `outline`·`crop`·`full`, 기본 `outline`) | `same_slide` |
| `SEEON_SLIDE_TEXT_BACKEND` | 화면 글자를 읽는 방법. `vlm` 은 화면을 읽는 서버, `ocr` 은 임베딩 서버(8804)의 글자 인식(`/ocr`, 주소는 `SEEON_OCR_URL` 로 바꿀 수 있음)이고 OCR 이 응답하지 않으면 VLM 으로 읽는다. 개발자 모드에서 고르면 그 값이 먼저다 | `vlm` |
| `SEEON_SUMMARY_LIVE_SEGMENTS` | 회의 중 구간 요약(`on`·`off`). 슬라이드 방문(또는 오래 머문 화면을 시간으로 자른 구간)이 닫히면 그 구간을 실시간 해설 요청이 없을 때 화면을 읽는 서버에 짧게 요약해 두고, 회의 뒤 요약은 이 구간 요약을 모아 만든다. 회의 요약 스위치를 끄면 하지 않는다. `off` 면 회의 중에는 하지 않고 회의 뒤에 모든 구간을 요약한다 | `on` |
| `SEEON_GPU_SSH_HOST` · `SEEON_GPU_SSH_USER` | 앱이 켜질 때 여는 GPU 서버 SSH 터널의 서버 주소·계정. 실제 값은 저장소에 두지 않는다 | 비어 있음 (비면 터널을 열지 않음) |
| `SEEON_GPU_SSH_PORT` | 그 서버의 SSH 포트 | `22` |
| `SEEON_GPU_SSH_HOST_FINGERPRINT` | 서버 호스트 키 지문(`SHA256:…`). 다르면 연결하지 않는다 | 비어 있음 (비면 터널을 열지 않음) |
| `SEEON_GPU_SSH_KEY` | 터널에 쓸 앱 전용 개인 키 파일 경로 | 비어 있음 (비면 터널을 열지 않음) |
| `SEEON_GPU_TUNNEL` | `off` 면 앱이 터널을 열지 않는다(따로 연 터널만 쓴다) | `auto` |
| `AWS_BEARER_TOKEN_BEDROCK` | Bedrock 키. 비우면 규칙 기반으로 대체한다 | 비어 있음 |

## 설치 파일 만들기

```bash
npm run dist:win        # Windows 설치 파일 — 맥에서도 만들 수 있어요(wine 불필요)
npm run dist:mac:dir    # 맥에서 설치본 동작만 확인할 때 — dist/mac-arm64/SEEON.app
```

- Windows 결과는 `dist/SEEON-Setup-<버전>.exe` (약 100MB)예요. `dist/win-unpacked/` 는 설치 전 내용물이에요.
- 설치본은 작업 파일을 `%APPDATA%\SEEON\out` 에, 회의 기록은 `문서\SEEON 회의 기록` 에 남겨요.

## 탐지 세부

정보 공백은 트리거 → 판단 두 단계로 가려내요.

1. **트리거** — 받아쓴 발화에서 후보를 뽑아요. 한국어는 형태소 분석(Kiwi) 뒤 품사로 맞추고
   ("같이 표를"의 "이", "저는"의 "저"는 잡지 않아요), 영어는 규칙으로 맞춰요.

   | 유형 | 예 | 채우는 에이전트 |
   |---|---|---|
   | 지시대명사 | 이 부분, 여기, 이렇게, this part, there | 지시 대상 설명 |
   | 형용사 + 지시 명사 | 빨간 쪽, 싼 거, the cheaper one | 지시 대상 설명 |
   | 단순 수치 | 30%, 12.5톤, 64 people | 발화 기반 설명 |
   | 변화·비교·결론 | 많이 올랐습니다, 결국 더 낮게 나왔습니다, more reliable than | 발화 기반 설명 |
   | 추상적 척도 | 꽤 넓죠, really big | 발화 기반 설명 |
   | 무발화 | 5초 이상 말이 없음 | 무발화 기반 설명 |

2. **판단** — 판정 LLM(Gemma 4 26B-A4B)이 후보마다 앞뒤 발화만 듣고 대상·값·정도를 알 수 있는지 판단해요.
   앞 발화는 마지막 화면 전환 뒤(최대 60초), 뒤 발화는 모드에 따라 몇 초(균형 모드 7초)까지 봐요.
   애매하면 말하지 않아요. 페이지 전환·화자 안내는 이 판단 없이 바로 만들어요.

## 안내 우선순위와 차단 규칙

| 순위 | 안내 |
|---|---|
| 0 | 직접 물어본 질문의 답 |
| 1 | 화면 전환 안내 · 화자 안내 (같은 순위, 함께 기다리면 화면 안내를 먼저) |
| 2 | 무발화 해설 |
| 3 | 발화 기반 해설 |
| 4 | 지시 해설 |

| 새로 생긴 안내 | 이 안내가 방금 나갔으면 쉰다 | 쉬는 시간 |
|---|---|---|
| 질문의 답 | 쉬지 않는다 | — |
| 화면 전환 안내 · 화자 안내 | 쉬지 않는다 | — |
| 무발화 해설 | 화면 전환 안내 | 12초 (무발화 해설끼리는 1분에 한 번, 슬라이드마다 한 번) |
| 발화 기반 해설 | 무발화 · 발화 기반 | 가리킨 곳이 있으면 12초, 말만 있으면 18초 |
| 지시 해설 | 무발화 · 발화 기반 · 지시 | 가리킨 곳이 있으면 12초, 말만 있으면 18초 |

- 덜 중요한 해설이 더 중요한 해설을 막지는 않아요. 순위와 상관없이 방금 한 안내와 사실상 같은 내용이면 말하지 않아요.
- 재생 차례를 8초 넘게 기다린 자동 해설은 버려요(질문의 답과 화면 전환 안내는 빼고). 재생 중인 안내를 끊는 건 질문의 답뿐이에요.
- TTS 는 이 규칙을 통과한 안내만 만들어요. 재생 차례가 가까운 2개는 미리 만들어 두고, 뒤에서 기다리다 버려지는 안내는 만들지 않아요.
- 들려주지 못하고 버린 안내는 "말한 것"으로 치지 않아서, 그 안내 때문에 다음 안내가 쉬거나 같은 내용이 막히지 않아요.
- 쉬는 시간과 막는 안내의 표는 `src/main/caption-pipeline/orchestrator/blocking-policy.js` 한 곳에서 고쳐요.

## 소리·재생 세부

- 동시 모드에서 안내가 나가는 동안 회의 소리를 −12dB 로 줄여요.
- 성능 프로필은 안내하는 동안 멈춘 회의를 1.5~1.8배로 빨리 돌려 따라잡아요.
- 질문의 답을 기다리는 동안(최대 20초) 자동 해설을 보류하고, 그사이 발표가 10초 넘게 지나간 해설은 버려요.

## 회의 기록 파일

- 개발 실행은 `out/summaries/` 에 `summary-session-<id>.txt`(요약 글), `summary-session-<id>.mp3`(요약 음성),
  `summary-session-<id>-script.txt`(회의 스크립트)를 남겨요.
- 사용자에게 보이는 기록은 `문서/SEEON 회의 기록/<날짜 시각> 회의/` 의 `대화 스크립트.txt`·`회의 요약.txt`·`회의 요약.mp3` 이고,
  같은 폴더의 `meeting.json` 에 회의 정보(시작·끝 시각, 제목, 슬라이드·발화 수)와 요약 상태 `summaryStatus` 를 둬요.
- `summaryStatus` 는 회의 뒤 요약을 만드는 동안 `pending`, 회의 기록에 요약 글을 저장하면 `done`,
  요약을 만들지 못했거나(구간 요약이 모두 실패한 경우 포함) 회의 기록에 저장하지 못하면 `failed` 예요.
  요약 기능을 끈 회의에는 이 칸이 없어요. 요약을 만드는 중에 앱이 꺼지면 다음 실행 때 `pending` 을 `failed` 로 바꿔요.
  지난 회의 목록·상세는 요약 글이 없을 때 이 상태로 `요약 만드는 중`·`요약 실패`를 보여요.

## 회의 요약 만들기

- 회의 뒤 요약은 구간 요약을 모은 통합 입력으로 초안을 쓰고, 귀로 듣기 좋게 다듬어 저장해요.
- 긴 회의에서 초안이 `슬라이드별 내용`까지만 쓰고 `결정된 것과 앞으로 할 일` 없이 끝나면, 같은 통합 입력으로 그 부분만 따로 만들어 붙여요.
  따로 만들다 실패하거나 답이 길이 한도에서 잘리면 초안을 그대로 써요.
- 초안이 통합 입력에 비해 크게 짧으면(입력 6,000자 이상에서 입력의 4분의 1 미만) 한 번 더 만들어 긴 쪽을 써요.
  다시 만든 쪽이 길이 한도에서 잘렸으면 처음 것을 써요.
- 요약 글의 숫자는 아라비아 숫자 그대로 둬요. 요약 음성을 만들 때만 음성 서버가 잘못 읽는 꼴(소수, 쉼표 숫자, 억·만 단위, 조사 앞 숫자, 퍼센트)을
  한자어 읽기로 바꿔 합성해요(`16.1을` → `십육 점 일을`, `4,043포인트` → `사천사십삼포인트`).
  날짜(년·월·일)와 개·명·장처럼 고유어로 세는 말 앞의 정수, 시각·전화번호·버전처럼 읽기를 정할 수 없는 숫자, 영문에 붙은 숫자(`RE100`·`GPT-4`)는 그대로 둬요.
  영어 요약은 바꾸지 않아요.

## 개발자 모드

머리줄의 `SEE-ON` 로고를 2초 안에 5번 누르면 **파이프라인 흐름 창**이 따로 열려요.
이번 회의에서 안내 후보가 단계마다 통과했는지, 어디서 왜 걸러졌는지, 실제로 재생됐는지를 보여 줘요.
이미 열려 있으면 그 창을 앞으로 가져와요.

개발자 모드를 열면 설정 패널 맨 아래에 **개발자 진단** 영역도 나타나요. 앱을 다시 켜면 다시 숨어요.
